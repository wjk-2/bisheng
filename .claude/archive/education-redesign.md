## 一、平台定位（已确认）

**高校智能体教学与实践平台**，依托 E-Agent 能力，面向高等院校提供从通识教育到专业实践的完整智能体学习路径。

学生学习的终态不是"看完内容"，而是"交付一个可运行的智能体作品"。

---

## 二、用户角色（已确认）

第一期聚焦三类角色，企业/合作方角色后续迭代。

| 角色 | 核心职责 | 入口 |
|------|---------|------|
| 学生 | 学课程、做实验、提交作品 | `/education`，角色决定视图 |
| 教师 | 建班级、分配课程、查看进度 | `/education`，角色决定视图 |
| 管理员 | 创建账号、分配角色 | `/education`，角色决定视图 |

三类用户同一入口，登录后系统按角色渲染对应视图，无需用户自己判断路由。

---

## 三、学生端场景（已确认）

**核心行为主线：学 → 做 → 交**

学生登录后直接进入课程学习界面，主线是知识获取，实操和提交作品是配套。

### 学习界面：图文 + 嵌入实操双栏

- 左栏：图文教学内容（知识点讲解、步骤说明、示例）
- 右栏：嵌入式操作区（直接在页面内操作 E-Agent 功能）
- 通识课右栏：简化操作面板，只暴露当前单元需要的功能
- 专业课右栏：完整编辑器（iframe 嵌入现有工作流编辑器、知识库页面）

### 数据归属：双轨

- 课程进度归班级——教师可查每个学生的完成状态
- 作品归个人——学生账号下永久保留，跨班级跨学期不丢失

### 第一期完成状态

- 每个单元只记录"已完成/未完成"
- 不做评分，不做能力画像，后续迭代

### 学生端功能清单

- 我的课程：查看已加入班级的课程列表
- 单元学习：双栏模式完成每个单元
- 作品提交：将实操产出提交到对应单元任务
- 个人作品集：历史提交作品的归档展示
- 学习进度：当前课程的单元完成状态

---

## 四、教师端场景（已确认）

**核心行为主线：建班级 → 分配课程 → 跟进学情**

教师登录后进入班级管理界面，课程内容由平台方预置，教师只做管理和监督，不修改任何教学内容。

### 班级管理

- 创建班级（班级名称、学期、关联课程）
- 导入学生（批量导入或手动添加学生账号）
- 管理班级成员（移除、查看状态）

### 课程访问

- 所有课程默认对全体学生开放，无需教师分配
- 教师无需做课程分配操作

### 学情跟进

- 班级进度总览：每个学生的单元完成状态
- 单元完成率：班级整体完成情况
- 作品查看：浏览学生提交的智能体作品

### 第一期边界

- 不做评分功能，只看完成状态
- 不做通知/消息功能
- 不支持教师修改或自建课程内容

---

## 五、管理员端场景（已确认）

**核心行为主线：账号管理**

管理员职责最小化，第一期只负责账号体系。

### 账号管理

- 创建账号（学生、教师）
- 分配角色（学生 / 教师 / 管理员）
- 重置密码
- 启用 / 禁用账号

### 第一期边界

- 不做课程内容管理（平台方直接维护数据库或后台脚本导入）
- 不做全局数据看板
- 不做批量导入账号（可后续迭代）

## 六、课程体系（已确认）

平台方预置三类课程，教师只选课不改课。

### 通识课

- 受众：全体本科生，零基础
- 规模：16学时，8单元，全程零代码
- 右栏形态：简化操作面板，按单元定制，只暴露当前知识点需要的操作
- 实践终态：提交个人智能体作品

| 单元 | 主题 | 实践终态 |
|------|------|---------|
| 1 | AI是什么：大模型的能与不能 | 和AI对话，找出3个它答错的场景 |
| 2 | Prompt基础：如何说话AI才听懂 | 完成5个指定任务的Prompt设计 |
| 3 | Prompt进阶：角色、结构、约束 | 写出一个专业领域的高质量Prompt |
| 4 | 知识库入门：让AI记住你的资料 | 上传文档，搭建一个个人知识库 |
| 5 | 智能体初探：配置一个AI助手 | 创建一个有人设和能力的智能体 |
| 6 | 智能体进阶：工具与场景设计 | 给智能体绑定知识库，完成问答场景 |
| 7 | AI伦理与边界：用AI要守什么规 | 完成一个AI伦理案例分析讨论 |
| 8 | 综合实战：做一个解决真实问题的AI应用 | 提交个人智能体作品 |

每单元 = 1小时理论内容 + 1小时上机实践

### 专业课

- 受众：AI / 计算机专业学生
- 规模：32-48学时（待定），5个阶段
- 右栏形态：完整编辑器（iframe 嵌入现有工作流编辑器、知识库页面）
- 实践终态：提交完整智能体作品集

| 阶段 | 核心能力 | 实验产出 |
|------|---------|---------|
| 基础层 | 大模型API调用、Prompt工程进阶 | 完成指定分类/摘要/生成任务 |
| 知识层 | RAG知识库构建、向量数据库、文档解析 | 搭建一个领域问答系统 |
| 编排层 | 工作流设计、节点编排、工具调用 | 设计一个多节点自动化流程 |
| 智能体层 | Agent设计、记忆系统、多智能体协作 | 完成一个自主决策的智能体 |
| 产品层 | 从原型到可用应用、发布与评测 | 提交完整智能体作品集 |

### 项目案例课

- 受众：高年级 / 研究生 / 产教融合场景
- 形态：项目制，一个真实业务案例贯穿多次课
- 右栏形态：完整编辑器（同专业课）
- 实践终态：交付可运行的企业级智能体项目
- 候选方向：智能客服系统、企业知识库问答助手、自动化报告生成流水线、多智能体协作完成复杂业务

| update_time | datetime | 更新时间 |

| id | int PK | 自增主键 |

| semester | str | 学期（如 2024-2025-1） |
| teacher_id | int FK | 创建该班级的教师 |
| status | int | 0=进行中 / 1=已结束 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

### ~~ClassCourse（班级-课程关联）~~（已删除）

所有课程默认对全体学生开放，班级不关联课程，此表不需要。

### ClassMember（班级成员）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 自增主键 |
| class_id | int FK | 关联 Class.id |
| student_id | int FK | 学生账号 |
| status | int | 0=正常 / 1=已移除 |
| join_time | datetime | 加入时间 |

### UnitProgress（单元完成状态）

唯一约束：`(student_id, unit_id, class_id)`——进度按班级维度记录，教师查看的是本班进度。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 自增主键 |
| student_id | int FK | 学生账号 |
| class_id | int FK | 关联 Class.id |
| unit_id | int FK | 关联 Unit.id |
| status | int | 0=未完成 / 1=已完成 |
| complete_time | datetime | 完成时间（status=1 时写入） |

### Portfolio（作品）

`unit_id` NOT NULL——第一期作品必须来自单元任务提交，不支持课外自由提交。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 自增主键 |
| student_id | int FK | 学生账号 |
| unit_id | int FK NOT NULL | 关联 Unit.id，必填 |
| class_id | int FK | 提交时所在班级 |
| asset_type | enum | agent / knowledge / workflow / text |
| asset_id | int | E-Agent 中对应资产的 ID（引用），text 类型时为 NULL |
| text_content | text | 文本作品内容，asset_type=text 时使用，其他类型为 NULL |
| title | str | 作品名称 |
| description | str | 作品简介（可选） |
| submit_time | datetime | 提交时间 |

### 表关系总览

```
Course（课程）—— 全体学生默认可见，无需分配
  └── Unit（单元）多对一

Class（班级）
  ├── ClassMember（班级-学生关联）多对多
  └── UnitProgress（单元进度）归班级

Portfolio（作品）归个人
  └── 关联 Unit + Class + 用户表
```

## 九、角色与权限扩展（已确认）

### 扩展方案

在现有 `web_menu` 枚举体系中新增教育专属权限值，与现有 Platform 权限体系保持一致。

**新增枚举值：**

| 枚举值 | 角色 | 说明 |
|--------|------|------|
| `education_student` | 学生 | 可访问课程学习、作品集 |
| `education_teacher` | 教师 | 可访问班级管理 |

管理员沿用现有 `admin` 角色，`education/accounts` 路由走 `ADMIN_ONLY_PATHS` 限制。

### 前端角色判断

登录后前端通过 `web_menu` 数组判断角色，渲染对应教育视图：

```
web_menu 含 education_student  → 渲染学生视图（课程学习、作品集）
web_menu 含 education_teacher  → 渲染教师视图（班级管理）
user.role === 'admin'           → 可访问账号管理
```

### 左侧导航实现

通过 `web_menu` 动态控制菜单项显示，复用 `MainLayout` 现有侧边栏渲染逻辑，不单独实现 sub-nav。
