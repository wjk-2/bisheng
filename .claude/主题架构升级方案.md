基于已落地的全部代码，当前架构如下：

E-Agent v2.3.0 主题系统架构（改造后）
数据层

MySQL config 表（key='web_config'）
  value 字段（Text）= JSON 字符串
    v1 旧格式: { comp: { '--primary': {h,s,l}, ... }, bg: 'logo' }
    v2 新格式: { light: { '--primary': {h,s,l}, ... },
                 dark:  { '--primary': {h,s,l}, ... },
                 bg: 'logo' }
后端完全透传，不校验结构。前端读取时通过 parseWebConfig() 自动兼容两种格式。

单一真相源

GET /api/v1/web/config（无鉴权）
  → 管理员配置的品牌主题（亮/暗各一套）

GET /api/v1/work/config（无鉴权）
  → 工作台品牌配置（logo、slogan 等，与主题无关）
两端前端在启动时均 fetch 同一接口，品牌主题只有一个来源。

Platform 数据流

页面加载
  index.html 内联脚本（React 之前）
    → 读取 localStorage 'theme'（'light'|'dark'）
    → fetch GET /api/v1/web/config
    → parseWebConfig() 解析（兼容 v1/v2）
    → window.ThemeStyle = { light, dark, bg }
    → injectThemeVars(当前模式的 comp)
        创建 <style id="theme-vars">
        写入 :root { --primary: 220 85% 65%; ... }
        （CSS 规则，非 inline style）

React 渲染
  DarkProvider (darkContext.tsx)
    → localStorage 'theme' → dark boolean state
    → useEffect: classList.toggle('dark') + localStorage.setItem
    → useEffect: 调用 window.__injectThemeVars(对应模式的 comp)

用户切换暗色模式
  → setDark(true/false)
  → <html> 加/移 .dark class → Tailwind dark: 前缀生效
  → __injectThemeVars() 重写 <style id="theme-vars"> 为对应模式的变量
  → CSS 变量立即切换

管理员编辑主题
  Theme 组件 (theme/index.tsx)
    → handleHSLChange: applyThemeComp() 立即写入 <style id="theme-vars">
    → debouncedSaveTheme(300ms) → POST { light, dark, bg }
    → applyTheme（还原默认）: 直接 POST（无防抖）
Client 数据流

页面加载
  ThemeProvider (ThemeContext.tsx)
    → useState: localStorage 'theme' → 初始主题
    → useEffect([]): fetch GET /api/v1/web/config
      → parseWebConfig() 解析
      → window.ThemeStyle = { light, dark, bg }
      → applyThemeVars(当前模式的 comp)
          创建 <style id="theme-vars">，写入 :root { ... }

用户切换主题
  → setTheme('light'|'dark')
  → rawSetTheme(): classList 操作 + localStorage + applyThemeVars(对应模式)
CSS 变量注入机制

<style id="theme-vars">          ← 动态注入的规则（优先级层）
  :root { --primary: 220 85% 65%; --border: 225 5% 27%; ... }

<link rel="stylesheet" ...>       ← index.css / style.css 静态规则
  :root { --primary: 240 100% 64%; ... }     ← 亮色默认值
  .dark { --primary: 220 85% 65%; ... }      ← 暗色默认值
优先级链（从高到低）：

:root inline style（已废弃，不再使用）
<style id="theme-vars"> :root {}（管理员自定义值，specificity 0,0,0）
index.css .dark {}（暗色默认值，specificity 0,1,0）
index.css :root {}（亮色默认值，specificity 0,0,0）
亮色模式：theme-vars 的 :root{} 覆盖 index.css 的 :root{}（同 specificity，后者文档位置更后 → theme-vars 覆盖）

暗色模式：index.css 的 .dark{} specificity 高于 theme-vars 的 :root{}。但 __injectThemeVars 在切换时重写 theme-vars 为暗色套的值，两者指向同一组暗色变量，不冲突。

主题状态层

localStorage key: 'theme'
  值: 'light' | 'dark'
  两端共享同一 key

迁移机制（一次性，首次加载时）：
  Platform: isDark='true' → theme='dark'，删除 isDark
暗色 --primary 值（已统一）
位置	值	颜色
Client style.css .dark {}	220 85% 65%	亮蓝
Platform index.css .dark {}	220 85% 65%	亮蓝
defaultDarkTheme['--primary']	{h:220, s:0.85, l:0.65}	亮蓝
组件颜色使用方式

替换前: bg-[#4658FF] text-[#140E35] border-[#E5EAF4]
替换后: bg-primary    text-foreground  border-border

Tailwind 别名链:
  bg-primary → hsl(var(--primary)) → <style id="theme-vars"> 中的值
  text-muted-foreground → hsl(var(--muted-foreground)) → 同上
  border-border → hsl(var(--border)) → 同上
